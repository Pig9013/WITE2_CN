# 师徽显示修复_v1.9.12——陆军师徽

**问题**：用户反馈（2026-11-15）「空军的师徽显示正常了，但是陆军的没有。这个仍然要修复，并且再核查一下，是否还有漏网之鱼」。

**结论**：v1.9.11 修的是「整名译名」这一条路（`第1装甲师.tga`），而**陆军的贴图名是运行时用两段拼出来的**：`Units.csv` 的 `Name`（如 `1st`）+ 空格 + `OBs.csv` 的 `Suffix`（如 `Panzer Division`）。两段各自查词典后再拼，于是英文 `1st Panzer Division` 变成中文的 `1st 装甲师`，而我们从没生成过这个名字——`第1装甲师.tga` 永远不会被查询。空军（`AirSym`）的文件名是整名，没有两段结构，所以上一版就正常了。

---

## 1. 贴图名是怎么来的

- EXE 里的格式串（UTF-16，无硬编码单位表）：
  - `//Sym//%s//%s.tga` —— 单段名
  - `//Sym//%s//%s %s.tga` —— **两段名，中间那个空格是格式串自带的**
  - `//AirSym//%s//%s.tga`、`//AirSym//%s//%s_air_default.tga`
- 数据侧对应的两段：
  - `Dat\CSV\<剧本>\Units.csv`：165 列，`Name` 是短词（`1st`、`XX`、`1393rd`、`OKH`），**没有 symbol/图片列**；`Type` 列 = `OBs.csv` 的 `ID`。
  - `Dat\CSV\<剧本>\OBs.csv`：120 列，`Suffix` 才是编制词（`Panzer Division`、`Infantry Division`）。例：`Units` ID 25 `Name=1st` `Type=9` → `OBs` ID 9 `Name=HQ` `Suffix=Panzer Group` → 拼出 `1st Panzer Group`。
- 复现度：按此规则拼 14 个剧本的 (Name, Suffix)，得到 21,687 个不同拼装名，**复现 2,076 个 `Sym` 基名中的 1,474 个（71%）**；剩下的 602 个是不带 Suffix 的整名单位（`'Blade' BR Force`、`1-19th US Combat Engineer Battalion` 这类），走 v1.9.11 的整名路径。

## 2. 为什么 v1.9.11 没修好（反证）

- v1.9.11 给四套语言包各发了 338 个**整名译名**副本，其中就有 `第1装甲师.tga`；用户在 2026-11-14 启动后反馈「空军正常、陆军没有」。
- 如果引擎查的是「整名翻译后的名字」，`第1装甲师.tga` 就该被命中——没命中，说明它查的是**分段拼装后的名字**：`1st` + ` ` + `装甲师` = `1st 装甲师.tga`。
- 词典里没有 `1st` 这类纯序号键（`^\d+(st|nd|rd|th) ` 开头的键共 3,088 条，但形如 `11th SS`，不是裸序号），中文 `Units.zh.csv` 里 `1st` 也照抄英文——两段各自本地化的结果恰好就是「英文序号 + 空格 + 中文编制词」。
- 空军为什么正常：`AirSym` 的文件名是整名（`1._NAGr 1.tga`、`1.(F)_AufklarGr 100.tga`），没有「Name + Suffix」结构，本地化后仍是整名；而且中文文件名能被引擎解析（`北空部队.tga` 等 3 个上一版副本生效即证明这一点，也排除了「ANSI 代码页写不出中文路径」这条假设）。

## 3. 修法

`mod/build_symbol_names.py` 改为**数据驱动**：从 14 个剧本的 `Units.csv` + `OBs.csv` 全量枚举 (Name, Suffix) 对，对每个语言包算出 `loc(Name) + " " + loc(Suffix)`，再从英文原图复制一份。整名命中词典的老路径（`whole`）保留。

```
payload\overlay\Dat\Art\{Sym,AirSym}\<国>\<拼装名>.tga              ← zh-CN
payload\variants\<code>\overlay\Dat\Art\{Sym,AirSym}\<国>\<拼装名>.tga ← zh-TW / zh-HK / zh-MO
```

- 规模：每语言包 **2,440 个 / 36.2 MB**（`Sym` 2,437 = 剧本拼装 1,480 + 兜底 622 + 整名 335；`AirSym` 3），四套 **9,760 个文件**，清单 `audit/symbol-art.json`；跳过 4（见 §5.1 撞名）。
- 同一英文名可能有多种切分（不同剧本切法不同），所以拼装表是 **一对多**：例如 `90th`+`Light Afrika Motorized Division` → `90th 轻型非洲摩托化师`，而 `90th Light Afrika`+`Motorized Division` → `第90轻型非洲师 摩托化师`。初版只存第一对，漏了 4 个名字。
- Suffix 自带尾巴的（`'Flieger Division (-)'`、`'US Infantry Regiment (+)'`）由 `loc_part()` 先拆尾、后接回；`_Alt` 同理。
- 简体不重复生成 `payload/variants/zh-CN/overlay`（启动器对 zh-CN 不读该分支），省 26.3 MB。
- 仓库体积：四套内容字节相同，git 按内容去重，工作树 +105 MB、对象库约 +26 MB。

## 4. 顺带修掉的最后一处缺口：185th Folgore 的 ASCII 引号

- 该译名是 `第185步兵师"闪电"`（ASCII 双引号），Windows 文件名不允许 `"`，所以生成器只能跳过——它是整轮审计里**唯一**的缺失。
- 口径与全仓库一致（`II 'Folgore'`→`第二“闪电”师`、`P-38G/H Lightning`→`P-38G/H “闪电”`），改为 `第185步兵师“闪电”` / 繁中 `第185步兵師“閃電”`。
- 改动落点（共 20 处）：`data/scenario_csv/translations/unit.zh.jsonl` 1 行、`unit.zh.qa.jsonl` 1 行、`build/scenario_csv_zh/<11 个剧本>/Units.zh.csv` 11 格、`payload/translations.json` 1 键、`payload/variants/<code>/translations.bin` 4 键、`glossary/master_overrides.json` 与 `glossary/reference_overrides.json` 各 1 处。
- 新增 `integration/fix_unit_name_quotes.py`（`--check` 守卫）：单位名里的 ASCII `"` 成对换成 `“ ”`；glossary 两表按**逐字节外科替换**，不重新 dump（否则 5,650 行缩进全变）。

## 5. 漏网核查（用户要求）

`python mod/build_symbol_names.py --audit`：按 14 个剧本逐一枚举「有英文原图的单位行」，算出该行的贴图名，再查副本是否在盘上。

```
audit zh-CN  有徽单位行 13388 / 需副本 1563 / 缺失 0
audit zh-TW  有徽单位行 13388 / 需副本 1563 / 缺失 0
audit zh-HK  有徽单位行 13388 / 需副本 1563 / 缺失 0
audit zh-MO  有徽单位行 13388 / 需副本 1563 / 缺失 0
Symbol-art audit: OK
```

四套语言包 100% 覆盖，含繁体各自不同的译名（`集團軍群` / `集團軍羣`）。

### 5.1 兜底：基础剧本 CSV 之外的单位

审计只覆盖 14 个基础剧本的 CSV——**DLC 剧本没有外部 CSV 可抽**，其中的专属单位（如 `11th SS Panzergrenadier Division`、`Grossdeutschland Panzergrenadier Division`）不在 (Name, Suffix) 表里，拼装名就生成不出来。

兜底规则（`fallback_pairs()`）：对「CSV 没覆盖、整名也没译」的 `Sym` 基名，按引擎可能用的第二段词表切分——

- 候选 Suffix = 全部 14 个 `OBs.csv` 的 `Suffix` 去重值，共 **967 个**（`Panzer Division`、`BR Heavy Anti-Aircraft Regiment`、`Ital. Infantry Division` …）；
- 在每个空格处切一刀，第二段命中词表就生成 `loc(前段) + " " + loc(后段)`；
- 覆盖 **413 个基名 / 622 个目标名**（每语言包），例如 `11th SS`+`Panzergrenadier Division` → `第11党卫军 装甲掷弹兵师.tga`、`Grossdeutschland`+`Panzergrenadier Division` → `大德意志 装甲掷弹兵师.tga`。

4 个跳过是**不可避免的撞名**（同一单位的不同拼写落到同一个中文名，只能有一张图）：

```
Fuehrer Begleit / Fuehrer Grenadier Panzergrenadier Brigade  → 元首随从部队 / 元首掷弹兵 装甲掷弹兵旅
Muncheberg Panzer Division（Muncheberg 与 Muencheberg）      → 穆恩蔡伯格 装甲师
5th Cosseria / 5th 'Cosseria' Ital. Infantry Division         → 第5科塞里亚 意大利步兵师
```

## 7. 仍未处理

- DLC 剧本的**数据表**不可抽取（无外部 CSV）：DLC 专属单位已按 §5.1 的 Suffix 词表兜底生成，但若某个 DLC 的 Suffix 用了 967 个已知值之外的写法，该单位仍会缺图（无法静态发现，只能靠实机反馈）。
- 词典里少数 Suffix 的译名本身有问题（例如 `AUS Infantry Division`→`德步兵师`、`BR Field Artillery Regiment`→`步兵师野战炮兵团`）：贴图会照样显示（我们复制的是词典算出来的名字），但显示的单位名是错的。属独立缺陷，另行处理。
- `Sym` 里 602 个不带 Suffix 的整名单位，靠 v1.9.11 的整名路径（335 个译名）覆盖；其中与 `unitInfo.csv` 的 `Text Display Name` 同名的部分（211 个）因为百科正文已恢复英文，本来就能命中原图。
