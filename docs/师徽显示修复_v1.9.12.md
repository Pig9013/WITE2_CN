# 师徽显示修复_v1.9.12——陆军师徽（方案已回滚）

**问题**：2026-11-15 用户反馈「空军的师徽显示正常了，但是陆军的没有。这个仍然要修复，并且再核查一下，是否还有漏网之鱼」。当日晚再次反馈：「第 1 装甲师，没有任何师徽。」

**结论**：本轮按「两段拼装名」补齐了 9,760 个中文名贴图副本，实机仍不显示。内存取证证明引擎拼师徽路径时用的是**本地化后的**单位名，且路径在第一个汉字处就被截断——请求的文件名根本构不出来，**靠改文件名这条路走不通**。四套副本已全部回滚，runtime 与游戏原版逐字节对齐。

---

## 1. 曾经成立、现在被推翻的假设

v1.9.11 的做法是「整名译名副本」（`第1装甲师.tga`），陆军仍全缺。据此提出：

- 贴图名 = `Dat\Art\Sym\<国籍码>\<名>.tga`（编辑器手册 p47 §7.3：tga ≤100×100、必须带 alpha、**文件名必须与单位名一致**、按国家存放）。
- EXE 格式串 `//Sym//%s//%s %s.tga` 里的空格是模板自带的，两段数据分别是 `Dat\CSV\<剧本>\Units.csv` 的 `Name`（`1st`、`XX`、`OKH`）与 `OBs.csv` 的 `Suffix`（`Panzer Division`），`Units.Type` = `OBs.ID`。
- 两段各自过文本钩子后拼：`1st` + ` ` + `装甲师` = `1st 装甲师.tga`，而 `第1装甲师.tga` 永远不会被查询。按此复现 14 个剧本 21,687 个名字中的 1,474/2,076 个 `Sym` 基名（71%）。

这个模型能解释「为什么整名副本没用」，但**没能通过实机检验**。

## 2. 决定性证据：引擎拼出的路径在第一个汉字处断了

对运行中的 `WarInTheEast2.exe` 用 `VirtualQueryEx` + `ReadProcessMemory` 全扫可读内存（约 1.11 GB），逐块找 ASCII 与 UTF-16 的 `//Sym//`：

```
D:\Tool\WITE2\WITE2_CN\mod\runtime\dat\art\//Sym//GE//1st ␀
```

- 该串 58 个宽字符后即 NUL：**没有**「装甲师」三个字、**没有** `.tga` 后缀。
- 进程里另外两处 `//Sym//` 是 EXE 的静态格式串（VA `0x106f38c`、`0x106f3b8`），不是拼装实例。
- 全进程 0 处 ANSI `//Sym//`。

即：引擎确实先取本地化后的番号，再往缓冲里追加后缀；后缀是中文，追加时路径在第一个非 ASCII 字符处终止。于是 `CreateFile`/`D3DXCreateTextureFromFile*` 拿到的是一个残缺路径，必然失败，引擎对缺图完全静默（`engine.log` 只有字体纹理行，无任何贴图报错）。

**推论**：只要单位名被译成中文，师徽就不可能通过「给文件改名」显示出来；反过来，只要不译单位名，师徽就正常——但这等于放弃部队名汉化。

## 5. 与本次并行的另一个问题：指挥官报告的方格盖图

用户 2026-11-15 报告：从指挥官报告点进部队详情后，背景变成一堆可点击的单位卡片盖住地图（正常应是表格 + 地图）。排查结论：

- `WarInTheEast2.exe` 在游戏目录与 runtime 的 sha256 相同，且与 `payload/package.json` 的 `game_sha256` 一致；`Dat\Art` 逐目录比对 missing 0（唯一差异是当时多出的 2,443 个贴图副本），`Gui` 338/338、`Tiles` 1,837、`photo` 3,473 全部 0 差异 → 不是文件丢失或版本漂移。
- 时间上唯一变化是 `Sym` 贴图数从 2,078 涨到 4,523（翻倍）。引擎启动时**整目录预载**师徽（原版 2,077 个 tga 在启动后两分钟内全部被读），数量翻倍有可能压到纹理池/枚举上限。
- 该 2,445 个多余贴图已随本次回滚清除，待用户重启后复核；若仍复现，再按「干净 runtime（无中文贴图、仅字体/Info/Scen overlay）」逐步二分。
