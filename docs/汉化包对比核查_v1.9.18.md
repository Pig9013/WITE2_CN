## 四、恶性 bug（预备兵库支援单位无法移动到战场 / 死机）

定性：如果它确实发生在这个包上，那是对我们 **v1.9.15** 的报告，不是第三方 mod 的问题——该包不含 1.9.16–1.9.18 的任何修复。

### 假设排序

**A. 归一化误伤（最像）**：v1.9.15 没有闸门，引擎内部的任意大小写变体串都会被翻译；支援单位流程里若某个 token（`reserve` / `support` / `ready` 之类）被译成中文，后续比较或再查表就失配，表现为按钮无反应或走进异常路径。

**B. 同串异义未拆分**：`CITY` / `DIS` / `TR` 这类串在同一份词典里既是数据又是标签（1.9.16 才有地址特化层）。

**C. 返回指针所有权（架构级残余风险）**：`translate()` 返回词典池里的静态 `WCHAR*`；若引擎在个别路径上释放或就地改写返回值，会造成堆破坏。此假设从未验证，1.9.16 之后也没有改变这一点。

### 已排除

- **缺 264 个 `Dat\CSV`**：EXE 运行期只读 `dat\info\*.csv` 与 `.\Dat\GenData\%s`；CSV 只用于编辑器导入/导出（0x534aa0 起全是 Export/Import 菜单串）。
- **Info 表塌行**：只影响信息面板正文，不参与战斗/支援逻辑。
- **字体 / GuiFonts / 行高**：48 项全替换、2,447 字形、行高差 1.5%。
- **`.scn` 被改**：0 处不同。

### 处置顺序

1. 换 1.9.18 复测（假设 A 的解药已在内）。
2. 若复现：在玩家包建空文件 `mod\logs\trace.on`，按同样步骤复现一次，回传 `mod\logs\native.log`；看崩溃前最后几条 `TRACE rva=...` 请求了哪些串。
3. 仍需二分时，可加「安全模式」开关（分别禁用 crest hook / 归一化 / 地址特化），逐项排除。

## 五、如果真有一个「译得更全」的包，它只可能走三条路

1. **运行期抓串 + 补词典（显示层）**：最安全。我们 1.9.18 已内置 opt-in trace，可直接产出「未译清单」再批量翻译。
2. **地址特化 + 短串白名单**：解决同串异义与 ≤4 字符短码（`RG`/`CITY`/`TOE`/`DIS`/`TR`）。
3. **改数据层（CSV / .scn / EXE）**：译得最全，但支援单位、装备、番号在引擎里既是显示名又可能是查找键；改掉就会出现「点不动 / 死机」。这正好能解释「预备兵库支援单位移动崩溃」。

我们的底线：只做显示层，不改原版数据；同串异义用地址特化拆开；短串不进归一化索引；美术/数据令牌钉死。
