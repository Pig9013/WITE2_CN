# 美术资源汉化审计（v1.9.7）

> 触发问题：玩家报告「地图上的小河只剩名字，一条小河都看不见」。
> 审计范围：`Dat\Art` 下全部 63 个美术目录、EXE 内全部图块路径模板、当前 72,225 条词典。
> 纪律：全程只读文件与静态取证，**没有启动过游戏**。

## 1. 症状与定位思路

玩家看到的两件事必须分开：

- **河名标签还在** → 标签来自地图数据（`Dat\Scen\*.map` 的 river 名），走文本渲染，不查图块；
- **河床图形没了** → 引擎按名字找 `Dat\Art\Tiles\RIVER\...\R*\.tga`，文件找不到就静默跳过（引擎不报错、不写日志）。

所以「名字在、图形不在」等于「路径拼错了」，而不是「美术资源被删了/被替换了」。

## 2. 引擎如何找到一张图块（EXE 取证）

`WarInTheEast2.exe` 的 UTF-16LE 字符串池（file offset `0x561c24`–`0x5623b0`，VA = file + `0x1200`）里，按顺序排列着下面这些相邻字符串——它们就是地图图块的完整寻址表：

| file offset | 字符串 | 作用 |
|:--|:--|:--|
| 0x561c24–0x561ce8 | `NONE CLEAR WATER ROUGH MOUNTAIN SWAMP WOODS FOREST CITY URBAN HVY_URBAN TUNDRA BOCAGE SAND DESERT` | 地形枚举，顺序与 `tileDrawOrder.txt` 一致 |
| 0x561d7c / 0x561d88 | `FERRY` / `IMPASSABLE` | 同上，追加两项 |
| 0x561da0 | `//Tiles//CUSTOM//CUSTOM_%3.3d.tga` | 自定义图块（前缀写死） |
| 0x561de4 | `//Tiles//TOWN//TOWN_%3.3d.tga` | 城镇（前缀写死） |
| **0x561e20** | **`//Tiles//%s//%s_%3.3d.tga`** | **通用模板：目录名 + 前缀都由 `%s` 给出** |
| 0x561e58 | `//Tiles//COAST//COAST%d_%3.3d.tga` | 海岸（前缀写死） |
| 0x561ea0 | `//Tiles//RIVER//MINOR//R%d_%3.3d.tga` | 小河专用（目录名写死） |
| 0x56200c | **`MINOR//`** | 小河的中间令牌 |
| 0x56201c | **`MAJOR//M`** | 大河的中间令牌 |
| 0x562030 | **`IMPASS//I`** | 不可通行河的中间令牌 |
| 0x562048 | `//Tiles//RIVER//%sR%d_%3.3d.tga` | 河流通用模板：`%s` 吃上面三个令牌 |
| 0x5620d8 | `//Tiles//RIVER//MAJOR//MR%d_%3.3d.tga` | 大河专用 |
| 0x562128 | `//Tiles//RIVER//IMPASS//IR%d_%3.3d.tga` | 不可通行河专用 |
| 0x562178 | `Loading all art files` | 美术加载日志（引擎失败时不打这条） |
| 0x5621b0 起 | `NONE BASE COAST TERRAIN CUSTOM ROAD TOWN PORT RAIL RIVER WEATHER HEXGRID BORDER ...` | 美术类别表（错译的大类名会被当描述看，不参与路径） |

同一池里还有其余族的模板（未逐一记录偏移，全部按字面写死或只吃数字）：

```
//Tiles//BORDER//BORDER%d_%3.3d.tga     //Tiles//RAIL//RAIL%d_%3.3d.tga
//Tiles//DRAIL//DRAIL%d_%3.3d.tga       //Tiles//ROAD//%s//%s_%3.3d.tga      ← 自名型，%s = AVERAGE/GOOD/POOR
//Tiles//FACTORY//%s.tga                //Tiles//FACTORY//%s_DAM.tga        ← %s = FAC_AFV 一类
//Tiles//PORT//PortSymbol-z0%d.tga      //Tiles//WEATHER//WT_SNOWFALL.tga   ← 前缀写死
//Tiles//HexB_1.tga                     //Tiles//tileDrawOrder.txt
//Sym//%s//%s.tga                       //AirSym//%s//%s.tga                ← 国籍码 / 单位英文名
//Photo//A%4.4d.bmp                     //Units//A%4.4d.tga                 ← 纯编号
//Gui//frame%s.tga                      //Gui//<国家> chip.tga              ← frame 吃 green/red/white/highlight
//Tiles//RIVER//%sR%d_%3.3d.tga
```

**推论**：凡是「目录名 / 文件名前缀」由字符串变量提供的模板，只要那个字符串在词典里，路径就会被翻成中文，文件必然找不到。`MINOR//` 正是这类键。

## 3. 路径模板全表与判定

判定口径：**该字符串是否参与拼路径**。

| 模板 | 参与拼接的字符串 | 字典状态（v1.9.6 时） | 判定 |
|:--|:--|:--|:--|
| `//Tiles//RIVER//%sR%d_%3.3d.tga` | `MINOR//` | **次要** ← 本次元凶 | **已修：移出词典** |
| 同上 | `MAJOR//M` | 不在词典 | 正常 |
| 同上 | `IMPASS//I` | 不在词典 | 正常 |
| `//Tiles//%s//%s_%3.3d.tga` | `AVERAGE` `CUSTOM` `FERRY` `GOOD` `HVY_URBAN` `IMPASSABLE` `SAND` `BOCAGE` `CITY` `CLEAR` `DESERT` `FOREST` `MOUNTAIN` `ROUGH` `SWAMP` `TOWN` `TUNDRA` `URBAN` `WATER` `WOODS` | 其中 8 个仍被翻译：AVERAGE=平均、CUSTOM=自定义、FERRY=渡运、GOOD=良好、HVY_URBAN=重型城市防御、IMPASSABLE=无法通行、SAND=沙地（另 MINOR// 见上） | **已修：8 键移出词典**（其余 12 个早已在 master_drops） |
| `//Tiles//ROAD//%s//%s_%3.3d.tga` | `AVERAGE` `GOOD` `POOR` | AVERAGE/GOOD 被译；POOR 被译但目录下只有 `EmptyCheck.txt`（故意无图） | 同上，一并移出（POOR 无害，为一致性也移出） |
| `//Tiles//COAST//COAST%d_%3.3d.tga` | 无（前缀写死） | COAST=海岸线（保留） | 安全：模板不含 COAST 变量 |
| `//Tiles//CUSTOM//CUSTOM_%3.3d.tga` | 无 | — | 安全 |
| `//Tiles//TOWN//TOWN_%3.3d.tga` | 无 | — | 安全 |
| `//Tiles//BORDER//BORDER%d_%3.3d.tga` | 无 | BORDER 已在 drops | 安全 |
| `//Tiles//RAIL//RAIL%d_%3.3d.tga` / `DRAIL` | 无 | RAIL 已在 drops | 安全 |
| `//Tiles//FACTORY//%s.tga` | `FAC_AFV`/`FAC_AIR`/`GENERIC-Factory` 等 46 个 | 词典零命中 | 安全 |
| `//Tiles//PORT//PortSymbol-*-z0%d.tga` | 无 | PORT 已在 drops | 安全 |
| `//Tiles//WEATHER//WT_*.tga` | 无 | WEATHER=天气（保留） | 安全：文件名字面量写死 |
| `//Photo//A%4.4d.bmp` `//Units//A%4.4d.tga` | 无（纯编号） | `photo`/`Units` 是词典键但从不作为独立串进路径 | 安全 |
| `//units//*.tga`（界面写死前缀） | `//units//` | **单位** ← 同类漏网 | **已修：移出词典** |

「自名型」的含义：`Dat\Art\Tiles\<DIR>\<DIR>_<idx>.tga` —— 目录名与文件名前缀是同一个字符串，通用模板 `//Tiles//%s//%s_%3.3d.tga` 一次吃两个 `%s`，所以只要「目录名」进了词典，这个目录下**所有**图块都画不出来。全库共 20 个自名型目录：

```
AVERAGE BOCAGE CITY CLEAR CUSTOM DESERT FERRY FOREST GOOD HVY_URBAN
IMPASSABLE MOUNTAIN ROUGH SAND SWAMP TOWN TUNDRA URBAN WATER WOODS
```

非自名型（模板把前缀写死，目录名只是目录名）：`COAST`(COAST0_*) `BORDER`(BORDER0_*) `RAIL`(RAIL0_*) `DRAIL`(DRAIL0_*) `WEATHER`(WT_*) `PORT`(PortSymbol-*) `FACTORY`(FAC_*) `ROAD`(无 tga，只有 AVERAGE/GOOD/POOR 三个子目录)。这批目录名即使被翻译也不影响加载。

`MINOR//`、`//units//`、`AVERAGE`、`CUSTOM`、`FERRY`、`GOOD`、`HVY_URBAN`、`IMPASSABLE`、`POOR`、`SAND`

### 5.2 顺带复活的 6 个键（构建顺序缺陷的连带产物）

它们同时存在于 drops 与 overrides 两层。原 `build_maps.py` 先执行丢弃层、后套用覆盖层，等于把这些键放了回来。修正顺序后一并消失。

## 6. 永久守卫（三道）

1. `mod/scan_art_tokens.py` —— 扫描 `Dat\Art`（33 个 Tiles 目录 / 63 个 Art 目录），按「目录内是否存在 `<DIR>_<idx>.tga`」机械判定自名型，产出 `glossary/art_tokens.json`（含 20 个自名目录、4 个路径令牌）。`--check` 可做一致性校验。
2. `mod/build_maps.py` —— 丢弃层移到覆盖层**之后**执行，drop 永远赢；丢弃清单解析失败不再静默。
3. `mod/finalize.py` —— 「美术路径守卫」：拒绝 ①key ∈ 自名型目录 ②key ∈ 路径令牌 ③key 匹配 `^[A-Za-z0-9_./]+$` 且含 `//`；对 key ∈ 图块目录名（模板写死那批）只告警。

守卫通过后 `finalize` 的实际输出：

```
Art-dir keys kept (template hardcodes the name): COAST, MAJOR, MINOR, WEATHER
Art-path guard: OK (20 self-named dirs, 4 path tokens)
```

## 7. 残留风险

| 项 | 说明 | 建议 |
|:--|:--|:--|
| `MINOR`=次要 / `MAJOR`=少校 | 裸词不进路径，但在地图编辑器语义里应是「小河/大河」；裸 `Major` 又确实可以是军衔 | 待确认上下文后再定，暂不留风险 |
| `green/red/white` | 只影响 `//Gui//frame%s.tga` | 若玩家反馈高亮框消失，移出这三个键 |
| Sym / AirSym 单位名 | 334 个 stem 精确命中词典 | 若出现「单位符号成片消失」，优先查这里 |
| 繁体包 | 三套繁体由简体底本生成，键集合必须一致 | finalize 的语言包守卫已强制 |

## 9. 边界（没有做到的事）

- **没有启动游戏**验证。全部结论来自 EXE 字符串池、文件树与词典三方比对；引擎在找不到图块时静默跳过、不写日志，所以也没有日志可查（`runtime/engine.log` 里只有字体纹理记录，且停在主菜单）。
- **无法静态追调用点**：EXE 内没有任何字符串的绝对地址引用（连 `Loading all art files` 都是 0 命中），说明它用运行时表 + 基址偏移访问，单靠静态分析无法证明「哪个函数把 `MINOR//` 送进了本地化查表」。因此 §0 的因果链强度是「强旁证 + 现象吻合」，不是编译器级证明。
- 真正确认仍需玩家进游戏看一眼——这也是 §8 把验证步骤写出来的原因。
