# 全剧本空军指挥部覆盖（v1.10.7）

- 触发：玩家 m01872「每个剧本都有各自的空军单位，空军指挥部，不止有你给我列的剧本，每个都要做匹配。」
- 结论：**本机 23 个剧本全部纳入**。有 `Dat\CSV` 的 12 个剧本，每个空军指挥部名都有确定归属（前缀守卫 / 恒等条目 / 载入窗口 / 无条目），`unsafe = 0`；这 12 个剧本的**航空作战群（AOG）名**共 4,010 条引用、去重 612 名，全部是恒等条目或前缀守卫（未钉死 0 名）。另外 11 个 DLC 剧本的 `.scn` 是加密容器，离线取不到单位名，但它们走的是同一个「载入期名字窗口」与恒等规则，与剧本无关（见第四节）。
- 审计工具：`integration/audit_air_hq.py`（`--check` 已接入 `mod/finalize.py`，构建时自动跑）。

## 一、三种归属与一条兜底

```
mod/src/text_hook.c:661-670   name_guard()   名字前缀守卫（Luftflotte / Luftwaffe / Flieger，排除 Field/Flak/Jaeger/… 等兵种词）
mod/src/text_hook.c:671-689   load_window    载入期名字窗口：w_weather.dat 打开，LockIn 关闭，上限 200 次
mod/src/text_hook.c（translate）恒等条目     词典值 == 键时交回调用方源指针
```

| 归属 | 含义 | 为什么安全 |
|:--|:--|:--|
| guard | 前缀守卫 | 载入时直接返回源指针 |
| pinned | 词典条目值等于键（恒等） | 恒等规则返回源指针 |
| window | 词典有不同译文 | 载入窗口内返回源指针；须通过 `name_like`（≤72 字符、不含 `% { } " : \ / \| =` 与控制字符） |
| absent | 词典无条目 | 原样透传，天然安全 |
| **unsafe** | 有译文但过不了 `name_like` | 窗口兜不住——本审计要求恒为 0 |

## 三、DLC 为什么离线枚举不了

11 个无 `Dat\CSV` 的剧本，单位表在 `.scn` 里：

- `.scn` 与 `.sav` 同头 `10 95 ff f9 …`，整体熵 8.0，`zlib` / `lzma` / `bz2` 全部解压失败——加密或私有压缩，不是能离线拆的容器；
- Steam 目录内除 `Dat\CSV` 外没有别的单位 CSV；`Dat\Save` 的 44 个 `.sav` 同样不可解；
- `Dat\Scen\<剧本>.txt` 只有历史简介与作者，没有战斗序列。

因此这 11 个剧本的指挥部名无法在构建期逐个列出，只能靠运行期机制覆盖。

## 四、为什么载入窗口与剧本无关（证据）

玩家 1941 Campaign 的 `native.log`（`D:\Tool\WITE2\WITE2_CN\mod\logs\native.log`）：

- 第 23040 行 `GenData\w_weather.dat` 开窗，第 23107 行 `5 LockIn gGameOption IN` 关窗；
- 窗口内 66 条查表，从 `Luftflotte 1` 到 `XII Troop Carrier Command`；
- **这 66 条里含 1941 剧本根本用不到的条目**：`RAF Transport Command`、`RAF Fighter Command`、`8th US Air Force`、`9th US Air Force`、`Malta Air Command`、`1st–4th Ital. Air Fleet`、`IX/XII Troop Carrier Command`、`Strategic Air Force`、`Coastal Air Force` 等；
- 还含**构词部件**：`15t`/`16t`/`17t`/`10t`/`11t`（番号，日志截字 bug 所致）与 `Air Arm`（`Air Army`），说明 HQ 显示名是「番号 + 兵种词」在载入时拼出来的。

结论：这张表是**全局空军指挥部名词表**，不是「本剧本单位表」。DLC 剧本载入时，它自己的
HQ 名（整体名或构词部件）同样进这张表，窗口照收；窗口上限 200、实测一次载入只用 66 条，
余量充足。

## 五、怎么复查

```powershell
# 人读矩阵（含每个剧本靠窗口的具体名字）
python integration/audit_air_hq.py

# 构建守卫（finalize.py 会自动调用；有问题退出 1）
python integration/audit_air_hq.py --check
# Air HQ guard: 23 scenarios (12 with CSV, 11 DLC), 28 window names (max 22 per scenario, budget 200; longest 15, limit 72); AOG 4010 refs / 612 distinct, 0 not pinned
```

实机判据（本机未启动游戏，工程纪律）：

1. 任选一个 DLC 剧本（AG A Part I 最直接）进游戏，打开「可用航空作战群」；
2. `mod\logs\` 下放空文件 `trace.on` 后再进一次，`native.log` 里该剧本载入段的名字查表应带
   `load`（窗口内交回源指针）或 `id`（恒等条目）；
3. 若仍为空，回传该次 `native.log`：看这个 HQ 名字是 `load`、`id` 还是 `exact zh`——`exact zh`
   说明它没进载入表，需要按名字单独处理。

## 六、边界

- 本审计覆盖「空军指挥部（AirHq）」与「航空作战群（AOG 名）」两条比对链；航空团/飞行团（AirGroups）的机队名不在筛选比对链上。
- 「无条目（absent）」去重后只有 16 个名字，且全是纯番号（`1st`、`2nd`…`127th`）：词典里没有裸番号条目，原样透传，天然安全。它们是引擎按「番号 + 兵种词」拼显示名的部件（与 native.log 里的 `15t`/`Air Arm` 同源）。
- 地图标签、城市名不受窗口影响（`Warsaw` 第 23326 行、`Rostov` 第 23348 行都在 23107 关窗之后）。
- 词典条目数不变（74,501），本项工作只加审计与守卫，不改译文。
