# Release v1.10.2（2026-11-19）

## 这次修好了什么

**一、航空队名的中文显示，这一版给了定论。** 玩家实测确认「可用航空作战群」列表在 v1.10.1 的常驻名称守卫下稳定可用。这一版把原因查到了底，并写进文档，避免下一轮再从文本层绕回同一个坑：

- 引擎比的是**名字对象**：同一份英文文本，v1.9.21 返回词典池里的英文副本时列表为空，v1.10.1 返回调用方自己的指针时列表正常。
- 引擎**从不调用**系统字符串比较函数：本轮把 `CompareStringW` / `CompareStringEx` 两个导入格换成转发函数，日志头写着 `cmp hooks: CompareStringW=1 CompareStringEx=1`，整局 23,623 行日志里 `CMP` 0 条。比较是内联的。
- 原地改写调用方缓冲区（实验开关 `inplace.on`）会污染引擎复用的字符串缓冲：日志里同一个键 `"Luftflotte "` 得到两个不同译文、`"Luftflotte 3"` 被截成「第3航空」。

结论：航空队/航空军 HQ 名保持英文原文，换取列表与筛选正常；约 24 个 HQ 名在其余界面也显示原文（与 v1.10.1 一致）。

**二、缩写同串异义（二期）。** 玩家报「苏军转场北方方面军的简写变成夜战」。EXE 里独立的 `NF` 只有三处，一条全局 `NF → 夜战` 把方面军代码表也盖了。现按地址拆开：飞机类型表与筛选下拉仍是「夜战」，方面军代码表译「北方方面军」；同时补 `FE`→远东、`SG`→苏联守备、`TC`→外高加索，`AG` 国码译「轴心国通用」，`BA`/`GD`/`NA` 三处按地址跳过。

**三、启动器偶发「未将对象引用设置到对象的实例」。** 读游戏进程模块基址加了重试，并用 `psapi!EnumProcessModules` 兜底；拿不到时给出可读错误并以英文运行，不再抛空引用。

## 怎么看某个游戏版本行不行

- 启动器标题显示 `1.10.2` 即为本版。
- 启动后看 `mod\logs\native.log` 头部：应出现 `addr overrides: 15`、`addr skips: 10`；打开「空中指令设置」面板，列表应有行，日志里应出现 `TRACE ... guard en "Luftflotte 4"` 与随后的 `%d %s`、`(E)`、`++` 行文本请求。
- 苏军转场面板/指令里出现「北方方面军」而不是「夜战」，即为本版缩写修复生效。
- 游戏打补丁后仍不拒绝启动：接入失败就以英文运行，存档与补丁不受影响。
