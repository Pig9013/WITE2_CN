# 枪炮译名比对（v1.9.8）

> 范围：`Devices.csv` / `Ground.csv` 里所有火炮、加农炮、榴弹炮、迫击炮、火箭与舰炮条目（544 条）。
> 目标：回答两个问题——**译不译**、**译成哪一种炮**——并给出可复核的判据，而不是凭语感。
> 铁律：本文件所有结论来自静态数据与公开文献，**没有启动游戏**。

## 1. 判定规则（本次定稿）

1. **炮种优先于型号**：中文名 = `口径/倍径 + 型号原文 + 中文炮种`，型号（KwK36、ZiS-3、Mk I、M1920）一律保留原文，不音译、不意译。
2. **以引擎分类为准**：`Ground.csv` 的单元名里已经写明 `AT Gun`/`AA Gun`/`Field Gun`/`Infantry Gun`/`Mountain Gun`，`Devices.csv` 的 `Type` 码（4 高射炮、5 车载/反坦克、6 直射炮、7 火炮、10 舰炮、25 舰用高射炮）是第二判据；两者冲突时以单元名为准（玩家看到的是单元名）。
3. **德式按原语**：`KwK`/`StuK` → 坦克炮，`Pak` → 反坦克炮，`Flak` → 高射炮，`Kanone` → 加农炮，`Haubitze` → 榴弹炮，`Gebirgsgeschütz` → 山炮，`Infanteriegeschütz` → 步兵炮，`Mörser`（含 600mm Karl）→ 臼炮。
4. **`Cannon` 分级**：20–37mm 自动/速射武器 → **机炮**（MG 151、BK 7.5、TNSh）；舰用或要塞大口径 → 加农炮/岸防炮。此前 18 条「机关炮」统一改为「机炮」，与维基词条一致。
5. **`Naval Gun` 一律「舰炮」**，不用「海军炮」；英制舰炮保留英寸写法（`15英寸/45倍径Mk I舰炮`），日制舰炮按日方习惯写厘米（`46厘米/45倍径九四式舰炮`）。
6. **日本年式译法**：`3YT`=三年式、`10YT`=十年式、`41YT`=四十一年式、`T94`=九四式、`Type 88`=八八式、`Type 98`=九八式；与中文维基「大日本帝国海军装备列表」的「45口径三年式12cm炮」写法对齐。
7. **英寸→毫米的边界**：有权威毫米值才换算（4.5in M1 = 114.3mm），否则保留英寸，避免「4.6in→150毫米」这种凭感觉的伪精度。
8. **`Rocket` 分弹与器**：弹体 → 火箭弹（RS-132、M-31、NbW 41）；发射装置 → 火箭炮。

## 5. 为什么会出现整批口径错误

`glossary/reference_overrides.json` 的 `terms` 组里有 19 条共享同一注记：

```
"口径单位统一为毫米（cm/in/mm → 毫米）"
```

即：不论原名写 `cm`、`in` 还是 `mm`，一律**把数字原样搬进毫米单位**。于是：

* `18.1in` → 「18.1厘米」（应为 460mm）；
* `15in` → 「150毫米」（应为 381mm）；
* `4.5in` → 「105毫米」（应为 114.3mm，可能是拿 4.2in=107mm 类比错的）。

该文件是 `integration/build_master_overrides.py` 的输入，而 `master_overrides.json` 是 `build_maps.py` **最后套用**的一层，优先级高于设备 jsonl。所以这 19 条既污染了初译，又在后续修订中把新译名压回旧值。

本次处置：

1. 19 条全部按 `1in = 25.4mm` 重算，注记改写为各自的换算依据；
2. 在 `_meta` 增加「勘误」字段，记下这条批量规则的失效；
3. `integration/build_master_overrides.py` 增加**丢弃层交叉核对**：若 `master_drops.json` 里的键又出现在覆盖层，直接 `SystemExit` 并列出键名，防止「死键复活」再次静默发生。

## 7. 与美术键（v1.9.7）的交接：`Art` 与 `City`

v1.9.7 把丢弃层（`master_drops.json`）排到覆盖层之后，本意是让「美术路径键」永不被译。副作用：**丢弃层里同时躺着两条 2026-11-04 才被有意恢复的 UI 定译**——`Art`（炮兵，EXE 类型表）与 `City`（指挥官报告列名）——会被一并吞掉。

处置：把这两条从 `master_drops.json` 移除（451 → 449 条），保留其 `reference_overrides.json → ui` 条目；另外 4 条结构性垃圾键（`UTF-8`、`american-english`、`_is_double`、`1 of 1`）继续丢弃，并从 `ui` 源头删除。

> 教训：**丢弃层不是「永久黑名单」**。任何一条被有意恢复的译名，都必须同时从 `master_drops.json` 撤下；否则「drop 优先」会把修复也一起吞掉。`build_master_overrides.py` 的新守卫会把这个矛盾变成硬失败，而不是静默。

## 9. 残留风险

1. **`master_overrides.json` 仍是「最后一道」**：任何设备名只要被手工加进覆盖层，设备表的修订就会被压掉。守卫只能拦住「丢弃层里的键复活」，拦不住「覆盖层写了个旧值」。建议后续把设备名从覆盖层彻底清空，让设备表成为唯一来源（本次未做，因涉及 5,650 条的整体职责划分）。
2. **英寸口径的炮种仍需人工确认**：如 `6.1in/55 M1920 Gun`（判为舰炮）、`4.5in/45 QF Gun`（判为高射炮），缺少权威型号出处，只保证「口径数字正确 + 炮种合理」。若后续查到原始型号，按 §1 规则 2 的优先级再校。
3. **日军年式与倍径写法**采用「`46厘米/45倍径九四式舰炮`」，与部分中文资料的「九四式45口径46cm炮」语序不同；如玩家反馈阅读障碍，可整批切换语序。
4. **未进游戏验证**：本文件的全部结论来自 CSV/EXE/字典静态比对，界面实际显示需玩家侧目视确认（重点看单位详情页的武器栏与情报报告里的装备表）。

## 10. 边界

* 不涉及飞机武器（`Aircraft.csv` 的 `Wpn` 列）以外的枪炮改判：本次只动 `Devices.csv`/`Ground.csv` 的火炮类条目。
* 不新增术语白名单：所有新译名都写进了 `equipment_name_fixes.json`，可逐条回滚。
* 口径换算只做「英寸→毫米」这一种，厘米/毫米原名保持不动。
