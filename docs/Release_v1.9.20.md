## 一、这次修好了什么

### 1. 地面分队名不再写成「第1/第56」（v1.9.20，940 条）

指挥官报告和单位面板里，「第1/第56 步兵师」这类两个「第」叠在一起的写法全部重算：

| 情形 | 例子 |
|:--|:--|
| 分队号 1–3，且该键在全部剧本里都配 Division | `1/56th` → 第56师第1团（显示「第56师第1团 步兵师」） |
| 同一键跨师/旅/团/营/连（`1/8th` 配过 6 种后缀） | `1/8th` → 第1/8，级别由后缀补 |
| 带附属词 | `I/3rd Lehr` → 第1/3 教导；`1/16th (158th Res)` → 第1/16（158预备）；`II/3rd Sturm (II/22nd)` → 第2/3 突击（2/22） |
| 党卫军师、空军番号、装备名 | 整条跳过，保持原译（`1/13th SS` → 第13党卫军第1营） |

引擎的单位名是「译(Name) + 空格 + 译(OBs.Suffix)」两段拼装（师徽文件名 `//Sym//GE//1st 装甲师.tga` 是硬证据），所以 Name 只能译成片段，兵种词由后缀补，不能自己再加一遍。

### 2. 航空部队番号补齐（v1.9.19，1,914 条）

指挥官报告 / 航空队列表里仍是英文的 **1,682 个航空队番号**、**232 个航空作战群（AOG）番号**全部译出，由仓库自有规则引擎 `glossary/air_designations.py` 生成，缩写先还原全称、罗马数字转阿拉伯、苏军写「近卫第N」：`II./JG 1`→第1战斗机联队第2大队、`Stab/FAGr 1`→第1远程侦察大队指挥部、`No.1 RAF FB Sqn`→皇家空军第1战斗轰炸机中队、`1 GBAP`→近卫第1轰炸航空团。**没有使用任何第三方汉化资源。**

同时修好场景表 12 个文件共 242 格把 `2/15 IAP` 截成「第2/第15」的旧缺陷（兵种词整段丢失），并加了一道构建守卫防止复发。

### 3. 可用航空作战群窗口词条（v1.9.18，8 条）

`rdy`→就绪、`Rdy:`→就绪：、`Req/REQ`→需求、`damaged`→受损、`AOG:`→航空作战群：、`Set formation counter color`→设置部队棋子颜色（原「设置队形计数器颜色」，那是把地图上的部队棋子误当成队形）；并顺带发布了一个**默认关闭的诊断开关**（见第三节）。

### 4. 党卫军串味与陈旧覆盖清理（v1.9.20）

`glossary/unit_name_canon.csv` 里 7 条按「场景表多数值」定的条目，把英军坦克旅、德军空军高炮营定成了「第33党卫军（法国）第1营」，已删除；真正的党卫军师是独立键，不受影响。另删掉 5 条压过新值的旧覆盖（`CCXIV/44th`→第114/第44 这类）。

## 三、怎么看某个游戏版本行不行

启动一次游戏，然后看 `mod\logs\native.log`：

- 正常：出现 `READY: hooked 2 call site(s)` 与 `first translation lookup succeeded`，界面即为中文。
- 钩子没挂上：出现 `FAILED: localization lookup not found in .text (build changed)`，游戏以下载的原版英文运行，不崩不卡。
- 想诊断某个界面为什么没译：在 `mod\logs\` 下建一个空文件 `trace.on`，复现一次，日志里会出现 `TRACE rva=... exact|norm|none|addr "<原文>"`（上限 20,000 条去重）。**看完请删掉 trace.on**，否则日志会持续增长。

## 四、已知限制（如实说明）

- 跨级别分队名（`1/8th` 同时配师/旅/团/营/连）只显示编号，级别由后缀补——这是「引擎按名查表 + 单键多义」的固有限制。
- `14/20th KH` 的 KH、`I/41st FR` 的 FR 语义未定，按原文保留。
- 「可用航空作战群」列表在中文版为空仍未定性；若你遇到，请按第三节开 trace 复现并提供日志。
- 百科正文、事件正文在游戏内仍英文：前者受引擎单字节渲染限制，后者在加密容器里。离线版百科见附件。
