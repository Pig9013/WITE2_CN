# v1.9.10 主菜单黑屏排查（2026-11-07）

用户在实机启动后报告：游戏主菜单（选剧本 / 难度 / 多人游戏那一页）**整页变黑、背景图消失**，按钮与文字仍在；进游戏后地图与地形正常。怀疑是「美工或 UI 被汉化」导致。

结论先行：**与汉化无关，也与美术资源被替换无关。** 原因是中文版私有运行时副本 `mod\runtime` 是 Steam 装 DLC 之前的旧拷贝，DLC 新增的 `Dat\Art\Gui\MainMenuSteelInferno.bmp` 从未被复制进去；引擎找不到背景图就静默跳过，画成黑底。启动器原来只在**主程序哈希变化**时才同步副本，而 Steam 这次更新只加资源、没动 EXE，所以永远不会触发同步。

## 1. 现象与排除路径

用户描述只有一条可用信息：**主菜单整页黑，按钮文字正常；地图正常**。

汉化能造成「图没了」的路径只有两种：

1. **替换了美术文件**——已排除。v1.9.7 审计时全仓库扫过：没有任何 `.tga/.bmp/.jpg`；payload 的 overlay 只有字体、`GuiFonts.json`、9 个 `Dat\Info\*.csv`、12 个 `Dat\Scen\*.txt`。
2. **翻译了参与拼路径的字符串**——已排除。EXE 的 UTF-16 字符串池里，主菜单相关全是**整条字面路径**：

| 字符串 | file offset |
|:--|--:|
| `gui/MainMenuSteelInferno.bmp` | 0x5b95d8 |
| `gui/mainmenu.bmp` | 0x5b96e0 |
| `gui/mainmenu_but.bmp` | 0x5b9778 |
| `//gui//mainmenu_but.bmp` | 0x5ba250 |
| `//Gui//MainMenuTile.bmp` | 0x5ba740 |

这些都是完整串，没有 `%s`；字典里也不存在这些整串（钩子是精确整串匹配，不做子串）。所以「UI 被汉化导致背景丢」这条路走不通。

剩下的只能是**文件不存在**。于是把游戏目录与私有副本做全量比对。

## 3. 为什么旧启动器不会自动补齐

`mod/src/Launcher.cs` 原 `Prepare()`（465–476 行）逻辑：

```
state = 读 marker (WitE2CN.runtime.json)
hash  = 主程序 SHA256
if state == null || state["game_sha256"] != hash:
    SyncRuntime(source, version, hash)   // 全量逐文件比对 + 复制
else:
    什么都不做
```

`SyncRuntime()` 本身没问题：遍历源目录全部文件，跳过 `Dat\Save\`、`engine.log`、`engine-prev.log`，按哈希比对后 `File.Copy(..., true)`。问题只在**它不被调用**。

Steam 装 DLC 的典型形态是：**只新增资源文件，不动可执行文件**。于是：

```
EXE 哈希不变 → marker 判定「同一版本」→ 跳过同步 → 新资源永远进不了副本
```

这也是为什么 11/5 之后用户进游戏一直看不到 DLC 的主菜单背景与事件图，而地图（Tiles 未变）始终正常。

## 5. 修法：启动器改为「内容漂移也同步」

`mod/src/Launcher.cs` 增加三个静态方法，并改 `Prepare()` 的判定：

- `TreeDigest(List<string> entries, long bytes)`：把条目排序后 `String.Join("\n")` 做 SHA256，返回 `"文件数:总字节:摘要"`。
- `TreeSignature(string source)`：遍历 `Files(source)`，条目为 `相对路径|大小|LastWriteTimeUtc.Ticks`，**排除 `Dat\Save\`、`engine.log`、`engine-prev.log`**（否则玩家在原版存一次档就触发一次全量校验）。
- `MissingFromRuntime(string source)`：只查「源里有、副本里没有」的存在性，同样排除存档与日志——防止玩家手工删掉副本里的某张图后，签名恰好不变而永远补不回。

`Prepare()` 新判定：

```
if 没有 marker || EXE 哈希变了:
    同步（日志：检测到游戏版本变化…）
else:
    sig     = TreeSignature(source)
    missing = MissingFromRuntime(source)
    if marker.tree 为空 || marker.tree != sig || missing > 0:
        同步（日志：检测到游戏资源有变化（Steam 更新或新增 DLC），正在补齐私有副本……
              若有缺失再加一行：私有副本缺少 N 个文件。）
```

两处写 marker 都补 `tree` 字段，现为：

```json
{"source":"d:\\tool\\steam\\steamapps\\common\\Gary Grigsby's War in the East 2",
 "game_sha256":"b1a81ff9e195c15518d867dcec48c8c07b319af294966640b174b9569e00ba61",
 "game_version":"1.0.5.02",
 "tree":"11337:1997460422:a0d1a310e1d12025a41dfda53ea6ef9eb0f68b370fd0d18aebd1ada41857c2fb"}
```

签名**排除 `Dat\Save\`**（游戏目录自带 148 个存档文件）与两份 engine 日志，所以是 **11,337 个文件 / 1,997,460,422 字节**，而不是全树 11,487——否则玩家在原版存一次档就会触发一次全量校验。

为什么不用「每个文件算 SHA256」：11,487 个文件、约 2.08 GB，每次启动都全量哈希要几十秒；`路径|大小|mtime` 签名一次约 1.0 秒，配合存在性探针已能覆盖「Steam 加/改/删资源」三种情况（Steam 会重写 mtime，实测 148 个文件全部落在同一分钟）。

编译（`mod/build_launcher.cmd` 末尾有 `pause`，脚本化时不要直接调它）：

```powershell
$csc = "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe"
& $csc /nologo /target:winexe /platform:x86 /optimize+ /codepage:65001 \
  /out:"D:\Tool\WITE2\WITE2_CN_repo\mod\WitE2CN.exe" \
  /r:System.dll /r:System.Core.dll /r:System.Windows.Forms.dll /r:System.Drawing.dll /r:System.Web.Extensions.dll \
  "D:\Tool\WITE2\WITE2_CN_repo\mod\src\Launcher.cs"
```

## 7. 残留与非本次范围

- **11 个 DLC 剧本简介仍是英文**：`payload\overlay\Dat\Scen\` 只有 12 个 `.txt`，游戏侧共 23 个。缺的是 `1943 Campaign.txt`、`1944 Campaign (May Start).txt`、`AG A - Part I - Race for the Caucasus.txt`、`AG A - Part II - Kuban Bridgehead.txt`、`AG C - Kutuzov to Bagration 43-44.txt`、`Case Blue Phase II 42-43 - Alternate.txt`、`Case Blue Phase II 42-43.txt`、`Drama on the Danube 44 - AI.txt`、`Drama on the Danube 44 - H2H.txt`、`Road to Karelia.txt`、`Western Ukraine 43-44.txt`。这些是「历史概述 / 战役概述 / 每回合行政点」的剧本简介，overlay 里已有 12 份中文版式可照抄。
- **7 个 DLC 新剧本的数据表未提取**：`data/scenario_csv/translations` 与 `build/scenario_csv_zh` 只覆盖 12 个旧剧本 + Generic，DLC 剧本的单位/事件/地名表既没进语料也没进翻译。
- **固定抖动**：overlay 的 19 个文件每轮会被 `SyncRuntime` 先拷原文再覆盖，导致签名在「刚 publish 完」与「跑过一次 Prepare」之间变化一次，多花约 6 秒；不影响正确性。
- **校验和边界**：`WitE2CN.exe` 不在 checksums 内，若玩家只替换启动器不会被判为损坏。

## 9. 边界

- 本会话按铁律**没有启动游戏**，「主菜单背景恢复」需用户实机目视确认。
- 「引擎读的就是 `MainMenuSteelInferno.bmp`」这一条无法静态证到 100%：EXE 里三条主菜单图路径都指向同一个加载位置（0x5b95d8 起连续三条），本报告的判据是「唯一缺失 + DLC 名 Steel Inferno + 与 `MainMenu.bmp` 同尺寸不同图」三条合取。即使引擎实际读的是别的图，本次补齐的 171 个文件也已经把 116 张事件图与 31 个剧本文件带回副本，属净收益。
