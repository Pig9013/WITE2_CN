# 缩写核查与地址特化（二期）

日期：2026-11-19　版本：1.10.1（同版本批次）

## 一、为什么会有「NF 变成夜战」

引擎里同一个短串常常身兼数职。以 `NF` 为例，EXE 里作为独立 UTF-16 字面量只出现 3 次：

| 文件偏移 | RVA | 所在表 | 正确含义 |
| --- | --- | --- | --- |
| 0x528D20 | 0x529F20 | 飞机类型筛选下拉（F/FB/NF/TACB/…） | 夜战（Night Fighter） |
| 0x5A48D4 | 0x5A5AD4 | 飞机类型码表（0x5A48C0，每项 10 字节） | 夜战 |
| 0x5CFBD8 | 0x5D0DD8 | 苏军方面军代码表（FE/SG/NF/TC） | 北方方面军（Northern Front） |

词典只有一张、按文本匹配，`NF → 夜战` 一条就把第三处也译成了夜战。这就是玩家在苏军转场里看到的
「北方方面军的简写变成夜战」。

## 二、修法：地址特化层 + 移除全局键

1. 从 `glossary/reference_overrides.json` 删除全局 `NF`；
2. 在 `glossary/addr_overrides.json` 的 `entries` 登记三处地址：
   - `0x529F20` → 夜战、`0x5A5AD4` → 夜战、`0x5D0DD8` → 北方方面军；
3. 顺带补齐同表的另外三个方面军代码：`0x5D0D88` FE → 远东、`0x5D0DA4` SG → 苏联守备、`0x5D0E00` TC → 外高加索。

地址层只在「引擎把该字面量的镜像内指针直接送进查表函数」时生效；若引擎先复制到缓冲区，则该条不生效，
界面退回英文 `NF`（比错译安全），不会产生新错误。命中会在 `mod\logs\native.log` 写 `ADDR override` 行。

## 三、同一轮里发现的其它缩写冲突

| 键 | 冲突 | 处置 |
| --- | --- | --- |
| `NF` | 飞机类型「夜战」vs 苏军「北方方面军」 | 地址特化（见上） |
| `BA` | 空战/任务枚举块里的 `BA`（DAM/DEF/ATT/BA/DF/BOMB…）vs 巴尔干战区码 | 0x52D120 跳过层，保持英文 |
| `NA` | 航空队编辑器/统计面板的 `NA`（N/A）vs 北非战区码 | 0x52F30C、0x52F314、0x5C6748 跳过层 |
| `AG` | 国别码 Axis Generic vs 最大指挥值「集团军群」 | 0x5C44D4 → 轴心国通用，全局键保留集团军群 |
| `GD` | 空中单位代码块 GV/GB/GI/GD/GS vs 「步兵师」 | 0x550CA8 跳过层，保持英文 |

## 四、核查范围与方法

- 取词典里 400 条 1–5 位全大写（含空格/斜杠）且含中文的短键，逐条在 EXE 里找「独立 UTF-16 字面量」
  （前后都是 NUL），记录地址；
- 按地址归类到已知码表区域：飞机类型表、类型筛选表、方面军表、战区盒表、国别码数组，
  再人工判读落在多个语义表里的键；
- 判据来自运行期 trace（`mod\logs\trace.on`）：引擎确实会把 .rdata 字面量指针直接送进查表函数，
  例如 `TRACE rva=52a5e8 exact zh "available air operational groups"`。

## 五、仍然无解的同类冲突（已知，记录在案）

- `Pol`（政治评分表头）vs 波兰国别码：国别码是 EXE 里的 ASCII 表，运行期转成宽字符副本，
  地址层抓不到；把全局键改成「波兰」会让指挥官报告的 `Pol` 列头变成「波兰」。暂保持表头正确。
- `Mor`（士气表头）vs 摩洛哥国别码：同上。
- `NO`：既是「否」对话框，又是挪威战区码；词典里本来就没有 `NO` 键，两面都安全。
- `Ira`：伊拉克与伊朗共用同一国别码，无法二分。
- `DIS`：战斗表里是「紊乱」、单位状态里是「解散」，已按地址拆分（0x52D0D4/0x58578C/0x5858A4/0x5937CC → 紊乱）。
- `TR`：飞机类型「运输」与任务设置短码冲突，已按地址拆分（0x5A5B10 → 运输，0x55C26C 保持英文）。
- `DET`、`DF`、`BOMB_TO`：语义无法确证，保持英文。
- `FF`（自由法国/战斗机）、`F`（筛选首项）、`JF`/`FP`（数据无机型）：保持英文。

## 六、怎么验证

1. 退到桌面→启动器→读档；
2. 打开苏军某航空单位的「转场」目标列表（或任何显示方面军的界面），看 `NF` 是否变成「北方方面军」；
3. 打开指挥官报告航空页，看类型列 `NF` 是否仍是「夜战」；
4. 退出后看 `mod\logs\native.log`：
   - `ADDR override rva=5d0dd8 ... -> 北方方面军` 表示方面军那处命中；
   - `ADDR override rva=5a5ad4 ... -> 夜战` 表示类型表命中；
   - 只有 `heap exact zh "NF"` 而没有 ADDR 行，说明该处是堆副本，需要换机制。
