# 同串异义与地址特化（v1.9.16 批次，2026-11-17）

## 现象

玩家反馈两条：

1. 「分配支援单位」窗口的列头仍是英文（`RG`、`CITY`），其余列（`SUPPORT UNIT`、`HHQ`、`TOE`）是中文。
2. 部队一览的检索框失效：输入 `guard` 会被翻成「近卫」，于是永远搜不到近卫部队。

## 结论

两条都不是「漏译」，而是**同一个字符串在不同位置承担不同角色**：

1. `CITY` 既是「分配支援单位」对话框的列头，也是 `//Tiles//` 地形图块目录名。v1.9.15 为了
   修道路/地形图块（把美术令牌钉死成英文）也把 `CITY`/`CUSTOM` 一起钉死，列头因此回退英文。
2. 检索框里的文字先被钩子的**归一化第二索引**接走：`guard` 去空白转小写后命中词典键
   `Guard` → 返回「近卫」，而列表里的部队名仍是英文数据，两边永远对不上。

词典只有一张、按文本索引，这类冲突在文本层无法两全。处置分三层。

## 处置一：地址特化层（新机制）

`mod/src/text_hook.c` 的 `translate()` 现在先比对**源串指针**：

    off = (ULONG_PTR)source - (ULONG_PTR)image_base;   // 主模块内偏移
    if (in_image(source) && addr_lookup(off, &hit)) return hit;

地址表由词典里的哨兵键带进来：键写成 `@@RVA:XXXXXX`（`parse_addr_key`），加载时**不进文本哈希**，
而是插进按 RVA 排序的 `addr_table`（`addr_push`/`addr_lookup` 二分）。加载结束写一行
`addr overrides: N`。

数据源是 `glossary/addr_overrides.json`（每条 `[译文, 原文, 说明]`），由 `mod/build_maps.py`
注入。当前 8 条：

| RVA | 译文 | 原文 | 位置 |
|:--|:--|:--|:--|
| `0x54B60C` | 城市 | CITY | 分配支援单位对话框列头（文件偏移 0x54A40C） |
| `0x5CA8B4` | 城市 | CITY | 分配高炮/工程单位对话框列头（0x5C96B4） |
| `0x54D1A0` | 自定义 | CUSTOM | 指挥官报告过滤条 `ALL / CUSTOM`（0x54BFA0） |
| `0x58578C` | 紊乱 | DIS | 战斗后详情·地面损失（0x58458C，手册 37.1.3） |
| `0x5858A4` | 紊乱 | DIS | 战斗后详情·地面战斗（0x5846A4，手册 37.1.4） |
| `0x52D0D4` | 紊乱 | DIS | 战斗后详情·空战编队紊乱（0x52BED4，手册 37.1.6） |
| `0x5937CC` | 紊乱 | DIS | 部队详情·地面要素表（0x5925CC，手册 37.3.2） |
| `0x5A5B10` | 运输 | TR | 飞机类型码 Transport（0x5A4910，Aircraft.csv Type 枚举） |

地址换算：`RVA = 段VA + (文件偏移 − 段raw)`；本文件用 `.rdata`（RVA 0x50C000 / raw 0x50AE00，
imagebase 0x400000）。回读校验脚本：`D:\Tool\WITE2\_tmp\rva_verify2.py`。

**生效条件**：只有引擎把**镜像内指针**（字面量地址）传给查表函数时才命中；若引擎先复制到
缓冲区，则该条不生效，行为与登记前完全一致（不会造成回归）。命中会写 `logs\native.log` 的
`ADDR override: rva=... out=zh|en` 行。

**防地址漂移**：`mod/build_maps.py` 的 `verify_addr_sources()` 在构建时按 RVA 读回游戏 EXE 的
UTF-16 字面量，与登记原文不一致就直接 `SystemExit`（失败而不是错译）。本轮输出
`Address sources verified: 8`。

## 处置二：归一化放行条件（检索修复）

`normalize_key()` 与第二索引本身不动，`translate()` 增加 `norm_allowed()` 判断：

- 含空白 → 放行（地图标签 `M o s c o w`、`Moscow` 这类仍能命中）；
- 全大写 ASCII → 放行（`MOSCOW`、`GENM` 这类仍能命中）；
- 其余仅当源串落在**主模块镜像内**时放行（代码里的字面量 `Rng`、`tacb`、`ew` 照旧翻译）；
- 堆缓冲里的小写单词（检索框里的 `guard`）不再归一化，原样交给引擎比对。

精确键不受影响——所以词典里 246 条全小写键（多为 `english-us` 这类语言代码）行为不变。
被拦下的会写 `NORM blocked (kept verbatim): src="guard"`（上限 120 行，便于查回归）。

## 处置三：支援单位一览与单位侧栏补译

`glossary/reference_overrides.json` 的 ui 组新增 8 条：`RG`→距离、`OHQ`→作战司令部、
`Ammo/Need`→弹药需求、`Supply/Need`→补给需求、`Fuel/Need`→燃料需求、
`Assign AA/CONST Unit to '%s'`→分配防空/工程单位到 '%s'、以及分配高炮时两条未译提示（requires 1 admin point to move flak to/from a city、requires 2 admin points to move this flak unit to/from this city）。手册依据：37.8（Pick Support Unit Type
窗口列 HHQ 与城市距离）、37.3（单位侧栏 OHQ = operational HQ）、21.5 Anti-Aircraft Units（调离城市按行政点计政治成本）。

## 验证

- 构建：`build_master_overrides` 6,144 → `build_maps` **72,566 条 / 9,454,438 B**
  （Art-token pins 10 + Address overrides 8）→ `complete_font` 2,447 字形 →
  `build_variants` 四语言包各 72,566 条、缺字 0 → `finalize` EXIT=0（19 道守卫）→
  `publish` 校验通过。
- DLL：`zig cc -target x86-windows-gnu -shared -O2 -s`，209,408 → **99,840 B**，
  sha256 `0038EA91…`，导出名仍为 `Wite2CN_Initialize@4`。
- `W2CN_TEST` 自测 PASS（含「同一字面量在登记地址返回中文、堆副本仍返回原文」与
  「小写 guard 不被归一化吃掉」两条新断言）；冒烟测试载入真实词典后 `addr overrides: 8`。
- 安装包实测：8 条 `@@RVA` 全在；`RG`→距离、`OHQ`→作战司令部、三条 `/Need` 全中；
  `CITY`/`CUSTOM`/`DIS`/`POOR` 词典值未变（符合「默认不动、只在该地址改」）。

## 限制与待确认

1. 地址条目的实际效果必须实机确认：进「分配支援单位」看列头 `CITY` 是否变中文，再查
   `logs\native.log` 是否出现对应 `ADDR override` 行。
2. 检索框里输入首字母大写的 `Guard` 仍会被精确键命中翻成「近卫」（已知残留）；
   小写 `guard` 已修复。
3. 游戏若更新，地址会漂移——构建期校验会拦住，需要重跑 `rva_verify2.py` 重新登记。
4. 仍未动的同串异义：`DIS` 在撤编状态处仍是「解散」、`TR` 的任务短码仍是英文
   （这两处的地址未登记，等实机确认后再决定）。
