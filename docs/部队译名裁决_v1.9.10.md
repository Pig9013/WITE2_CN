> 对象：`audit/semantic-unresolved.csv` 里 **103 条 family=unit 的语义冲突**（实际处理 100 键，3 条假阳性剔除）。
> 产物：`glossary/unit_name_canon.csv`（100 行，可复核）+ `integration/fix_unit_names.py` + `Unit-name guard`。
> 铁律：工程侧不启动游戏；`--selftest` 允许。

## 1. 这批冲突的真实形态

| 形态 | 例 | 说明 |
|:--|:--|:--|
| jsonl 带英文残渣 | `156th维琴察师`、`41st 爱沙尼亚步兵师`、`27th '塞克勒'`、`Kuliev骑兵`、`Mishulin的骑兵` | 数字/名字没译干净 |
| jsonl 罗马数字算错 | `DXXXV`→第335师（应 535）、`DV`→特遣队（应 505）、`LI Mountain`→LI山地（应 51）、`I Airborne`→空降师 I（应第1） | 与场景表冲突的主因 |
| jsonl 语义误译 | `IV Felderrnhalle`→第四帝国大厅、`I/S. Berlin Heimat`→I/S. 柏林家乡、`Luftflotte Reich`→Luft舰队、`Panzer Group West`→装甲集群西方 | 德文词被当英文 |
| jsonl 丢了编制级 | `1st Baltic`→波罗的海第1军（方面军写成军）、`2nd Baltic`→波罗的海第二集团军群 | 级次乱 |
| 场景表过短 | `West`→西方（应为西线）、`Western`→西方（西方面军）、`Southern`→南方（南方面军） | 短名把专名削成方位词 |
| 同键多值 | `310th RVGK` 同表两行：加农炮团 / 榴弹炮团；`544th` 两行 10:10 | 字典只能取一值 |

## 2. 口径：短名制，但专名不削

- 场景表 95% 的单元格是 **「第N+名称」** 短名（第156维琴察、第3波罗的海、第54海军），本批沿用，**不补**英文里没有的编制词（师/军/旅/团）。
- 例外：**方面军、集团军群**在中文里是番号的组成部分，写全——`白俄罗斯第1方面军`、`波罗的海沿岸第1/2/3方面军`、`西方面军`、`南方面军`、`A/B/C/E集团军群`、`北乌克兰集团军群`、`维斯瓦集团军群`。
- 级次判据：苏军 Type 2041/2042/2059 族 = 方面军；jsonl 旧值也出现过「方面军/集团军群」字样，两者互证。
- 已知限制：`LI Mountain`（第51山地军）、`I Airborne`（第1空降军）按短名制未补「军」，本轮只保证数字正确。

## 3. 判据来源

1. **场景表多数值**（73 键）：同键在 12 个剧本的 Units/UnitRenames/OBs 里出现最多的写法，平票取更长、更具体者。
2. **人工裁决**（27 键，source=fix）：语序、词义、编制级、语种——`North Caucasus`→北高加索（North 是地名前缀，不是「北方」）、`Southern Urals`→南乌拉尔、`Luftflotte Reich`→帝国航空队、`Panzer Group West`→西线装甲集群、`I/S. Berlin Heimat`→柏林第1本土部队、`Fallschirm`→伞兵（token 表）、`Feldersatz`→野战补充、`Frontier Guard`→边防警备（不是近卫）、`Schmalz`→施马尔茨、RVGK 六条→最高统帅部预备队第N…
3. **不按「哪个层出现次数多」投票**：场景表也会错（`West`→西方、`3rd Baltic`→第三巴尔蒂克军、`310th RVGK`→加农炮团），jsonl 也会对（`1st Belorussian`→白俄罗斯第1方面军）。取「多数」只是起点，语义以英文原文 + 语种为准。

## 5. 落地与三个坑

- `integration/fix_unit_names.py`：读 `glossary/unit_name_canon.csv`；jsonl 按 `text` 精确匹配写 `translation`（含 `.qa.jsonl` 副本）；场景表按**英文源表同一行列**定位，只改 `Units/UnitRenames/OBs`；写盘前字节往返校验，不一致即拒写；`--check` 有残留返回 2。

1. **OBs 的番号在 `Suffix` 列**，不在 `Name`。只改 `Name/newName` 漏掉 13 个文件里的 `Rum. Frontier Guard Division`，重建后仍是旧值「罗马尼亚边防近卫师」——这是本轮唯一的返工点。
2. **`GameEvents.zh.csv` 是 500+ 列宽参数表**，同名英文格是事件脚本参数，绝不能按值替换；本脚本按文件名白名单 + 列名白名单双重限定（与批次六同一铁律）。
3. **三张词表要查**：`build/translation.csv`、`data/translations/unit_names_en_zh.csv`、`mod/assets/translation.csv` 会被 `build_maps.py` 优先读取。本轮 5 处命中（A/B/E 集团军群、北乌克兰、维斯瓦）值已与 canon 一致，无需第三层修。

## 6. 守卫与复现

- `mod/finalize.py` 的 `Unit-name guard`：调 `fix_unit_names.py --check`，非 0 即 `refuse: Unit-name 未落地`，与 Semantic/Place-name 守卫同一段逻辑。
- 复现：

```powershell
python integration\fix_unit_names.py --check   # 0 残留 → UNIT-NAME-FIX: CHECK OK
python mod\build_maps.py
python mod\complete_font.py
python integration\build_variants.py
python mod\finalize.py                          # Unit-name guard / Layer guard
python mod\publish.py
```

## 7. 残留风险

1. **同串异义无法分离**：字典键就是英文字符串，`Ferdinand`、`Rifle Squad`、`Neame` 这类跨实体同名只能整体跳过，留给单条语境处理。
2. **短名制丢编制词**：`LI Mountain`、`I Airborne` 等未补「军」，与场景表既有风格一致，但与严格军语写法有差。若要补，须按 Type 族批量补，不能逐条拍脑袋。
3. **RVGK 同键多值**只能取多数（310/330/331/544/590 取榴弹炮团、594 取加农炮团）；被牺牲的那一行在 UI 上会显示成另一种兵种。
4. **SS 番号与国籍缩写**不在本批：`1/13th`→第13党卫军第1营等已由批次四（`fix_ss_names.py`）管；本批 canon 只收录 unit 层剩余的 100 键。
5. 未做游戏内目视：本轮仍是静态审计 + 离线 `--selftest`。
