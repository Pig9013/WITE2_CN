# 师徽显示修复_v1.9.11

**问题**：用户反馈（2026-11-14）「英文版单位详情页会有师徽，中文版师徽都没有显示」。

**结论**：师徽不是数据表里的字段，而是**按单位名查表的贴图文件**；名字被译成中文后，引擎按中文名拼路径，文件不存在，师徽静默消失。修法是把原版英文名贴图**按译名复制一份**，不改 EXE、不改 `.scn`、不改单位名。

---

## 1. 师徽在哪

```
Dat\Art\Sym\<国籍码>\<单位名>.tga        ← 师/军/集团军群徽标
Dat\Art\AirSym\<国籍码>\<航空部队名>.tga  ← 航空部队徽标
```

- `Sym` 共 2,077 个文件，国家码目录：AS BE BR BZ CA CN CZ FF GE GR HU IN IT NL NZ PO RU SA SL SU US。文件名就是单位英文名，另有 6 个 ` (+)`、5 个 ` (-)`、2 个 `_Alt` 后缀变体。
- 引擎侧的装载路径来自 EXE 里的格式串（UTF-16）：`//Sym//%s//%s.tga`、`//Sym//%s//%s %s.tga`、`//AirSym//%s//%s.tga`、`//AirSym//%s//%s_air_default.tga`。**没有硬编码单位表**，全靠文件名拼接。
- 反证「美术没丢」：`payload\runtime\Dat\Art\Sym` 与游戏原目录**逐国文件数完全一致**（GE 1,113、US 289、BR 275、IT 270、FF 44、CA 29、SU 18、HU 4、IN 9、PO 9、NZ 3、SA 4、SL 2，其余各 1，共 2,078 个 / 32.7 MB）。

> **更正（v1.9.12）**：本节结论只对「整名译名」成立。实测空军正常、陆军仍缺——陆军的贴图名是 `Units.csv` 的 `Name` + 空格 + `OBs.csv` 的 `Suffix` **两段各自本地化后拼装**的，详见 `docs/师徽显示修复_v1.9.12.md`。

## 2. 为什么中文版整片消失

- 词典（`payload\translations.json`，72,251 条）把 2,077 个贴图基名中的 **333 个**译成了中文；四个语言包合计派生 338 个译名（Sym 335 + AirSym 3）。
- 1941 Campaign 的 `Units.csv` 有 5,310 个不同单位名，其中 3,820 个（71.9%）有中文译文；**该剧本里有师徽文件的 79 个单位名，79 个全部被译成中文**——所以不是「个别单位缺徽」，是整片消失，与用户描述一致。
- 例子：`1st Panzer Division`→第1装甲师、`11th SS Panzer Army`→第11党卫军装甲军、`Army Group Center`→中央集团军群。
- 引擎对缺图**完全静默**：`runtime\engine.log` 350 行里没有任何贴图/美术报错，也不写日志；所以这个缺陷从 v1.5 起一直没被守卫发现。

## 3. 修法

新增 `mod/build_symbol_names.py`：对每个语言包，把「英文名.tga」按该语言包的译名复制成「中文名.tga」。

```
payload\overlay\Dat\Art\{Sym,AirSym}\<国>\<译名>.tga            ← zh-CN
payload\variants\<code>\overlay\Dat\Art\{Sym,AirSym}\<国>\<译名>.tga  ← zh-TW / zh-HK / zh-MO
```

- 启动器本来就每次启动把 `payload\overlay` 覆盖进 `runtime`（`mod/src/Launcher.cs:520-562`），简体还额外走 `payload\variants\zh-CN\overlay` 的**只有非 zh-CN 才读**的分支——所以简体不需要重复生成，脚本里已跳过 zh-CN 变体。
- 后缀 ` (-)` / ` (+)` / `_Alt` 先拆后缀查词典、再原样接回。
- 跳过规则：译名含非法文件名字符、首尾空格/点、>120 字、目标名已被原版占用、译名互撞（记进清单 `audit/symbol-art.json`）。
- 规模：每语言包 **338 个 / 3.1 MB**，四套 **1,352 个 / 12.49 MB**；跳过 0 个。

## 4. 顺带发现的译名缺陷：Army Group F/G/H

- 三个集团军群在词典里都被译成 **「集团军群」（字母被吃掉）**：jsonl 原文是 `集团军群G/集团军群H/集团军群F`（字母在**后**，同样错），11 个剧本的 `Units.zh.csv` 共 33 个显示单元格是 `集团军群`。
- 后果：三个单位同名，且只能共用一张 `集团军群.tga`——另外两张师徽被生成器判为撞名跳过。
- 修法：`integration/fix_army_group_names.py`（`--check` 守卫），一次改齐四层——`unit.zh.jsonl` 3 行、`build/scenario_csv_zh/*/Units.zh.csv` 33 格、`payload/translations.json` 3 键、`payload/variants/*/translations.bin` 4 包 × 3 键（zh-TW `F集團軍群`、zh-HK/zh-MO `F集團軍羣`）。口径与 `glossary/unit_name_canon.csv` 既有的 `A/B/C/E集团军群` 一致：字母在前。
- 改完重新生成：Sym 335 个、跳过 0，F/G/H 各得一张徽。

## 5. 守卫

- `mod/finalize.py` 新增 Symbol-art guard：调用 `build_symbol_names.py --check`，清单里 1,352 个副本缺一个就拒绝出包。
- 生成顺序：`build_maps.py` → `build_variants.py` → `build_symbol_names.py` → `finalize.py` → `publish.py`。
- `integration/build_variants.py` 的 `convert_overlay()` 增加 `BINARY_SUFFIXES`（.ttf/.otf/.ttc/.tga/.bmp/.jpg/jpeg/.png/.wav/.ogg）跳过，否则 overlay 里的 .tga 会被当 UTF-8 文本读而崩。

## 6. 顺带修掉的同源缺陷：unitInfo.csv 百科正文

- 勘察本轮时发现 `payload\overlay\Dat\Info\unitInfo.csv` 的百科正文整表被覆盖成同一句「约翰·汤姆林森提供」（1,168 行 distinct=1；原版同文件 1,168 条不同正文，平均 1,765 字）。该缺陷与师徽无关，但同一个 overlay 目录、同一批生成脚本，已在本版一并修复。
  根因：`data/translations/info_descriptions.zh.jsonl` 的 1,168 条 unitInfo 记录 `row_id` 全是 `"0"`（正文含换行导致按行号提取错位），而游戏 `unitInfo.csv` 的 `id` 列只有 `0`/`12` 两个值，`build_maps.py` 的 `descriptions[(p.name, row[ii])]` 只剩一个键、最后写入值覆盖全表。
  修法：正文由引擎直接读 CSV、单字节代码页显示不了中文，故恢复成**与游戏原版逐字节相同**的英文正文（2,126,770 字节，`mod/restore_unit_info.py`），并在 `build_maps.py` 里把该文件列为 verbatim 跳过、`finalize.py` 新增正文守卫。详见 `CHANGELOG.md` 批三。
