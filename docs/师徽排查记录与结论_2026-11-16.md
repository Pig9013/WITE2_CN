## 1. 机制（静态反汇编 + 运行进程转储确认，可复用）

- 师徽是**按显示名查表的贴图**：`Dat\Art\Sym\<国码>\<名>.tga`，机徽在 `Dat\Art\AirSym`。编辑器手册 `Manuals\WITW Editor manual EBOOK.pdf` p47 §7.3：≤100×100、**必须带 alpha**、**文件名必须与单位名一致**、按国家存放。
- 宽格式串（RVA）：`//Sym//%s//%s.tga` = `0x5cf38c`，`//Sym//%s//%s %s.tga` = `0x5cf3b8`（有后缀时用，中间是空格）。
- 唯一师徽调用点：**RVA `0x3ef56e`**（由「`push` 格式串的地址」反查得到，两条格式串都收敛到这一点）→ 加载器 **RVA `0x44dc30`**。
- 加载器：`sub esp,0x400`（1024 字节 **ANSI** 缓冲）→ `call 0x4368c0`（拼绝对路径）→ `call 0x4461c0`（纹理管理器）→ `ret`（cdecl）。
- 宽转窄：`0x44b1f0` 数宽字符 → `new(n+8)` → `call 0x4c310a` = **MSVC `wcstombs`**；静态链接 CRT、C locale，导入表里**没有** `setlocale` / `wcstombs`。
- **结论：非 ASCII 文件名在 CRT 转换处必然失败（EILSEQ）**，缓冲还按字符数分配（中文需 2 倍字节）。空军机徽文件名是 ASCII（`1._NAGr 1.tga`），所以空军一直正常。

## 3. 问题到底卡在哪

- **机制已经查清，不需要再猜**：非 ASCII 文件名必然在 `wcstombs` 处失败；这是静态 CRT + C locale 的死结，数据层（改文件名、加副本、改词典）**在任何情况下都不可能绕过**。
- **唯一可能有效的修法**：在 `0x3ef56e` 调用前把宽路径里的中文名换回英文原名（映射表 1,563 条已做过，格式 `W2CNCR1`）。这条路**从未得到一次真实验证**——最后一版已经正确锁定唯一调用点、只打 1 个补丁、放独立线程，但没跑过。
- 当时列出的四个风险点（纹理缓存键、`0x4461c0` 纹理管理器键、国码目录不一致、二次 ANSI 化），**实机结果说明都不成立**。
- 一句话：**机制清楚、修法明确，2026-11-16 实机验证成立**（见 §8）。

## 4. 我在这一轮里犯的错（复盘）

1. **先动手、后取证**：没有先建立观测（钩子日志）就批量生成贴图，四轮命名假设全部靠"用户重启看一眼"验证，每轮 10 分钟以上，把用户拖进无效测试。
2. **从汉化包倒推引擎**，而不是先读游戏自带手册与实现；用户明确要求"先搞明白原游戏怎么实现"之后我才做静态分析，白白多绕两轮。
3. **观测手段选错**：atime、彩块诱饵在"引擎静默 + 启动器全量同步"下都是噪声，我却把它们当判据。
4. **违反自己定的铁律**：往游戏原版目录写诱饵、覆盖了原版 `V Panzer Corps.tga`（靠 Steam 校验才恢复）、把诱饵塞进 runtime。
5. **一次改动太大**：256 个调用点全挂 + 每条路径写日志，直接把可用的中文版弄成超时、卡顿。
6. **碰了不该碰的 ABI**：IAT 钩 `D3DXCreateTextureFromFileExA`，一崩就是整游戏闪退。
7. **失败后只换猜测、不缩范围**：真正该先做的是"用最小代价拿到引擎请求的文件名"，这一步拖到第 10 次尝试才做到。

## 6. 当时设想的最小验证路径（已按此执行成功）

1. 装 zig（`pip install ziglang`，已验证可用）→ 从 `mod/src/text_hook.c` 编 DLL。
2. 只做一件事：在 `0x3ef56e` 处把 `//Sym//GE//1st 装甲师.tga` 改写成 `//Sym//GE//1st Panzer Division.tga`，写一行 `S|返回码|原|改写后` 到 `mod\logs\crest.log`。

## 7. 教训（写给以后）

- 机制没查清之前，不要生产美术资源；一次实机验证的成本远高于一次反汇编。
- 观测必须**便宜且只读**：先拿到"引擎请求了什么"，再谈修法。
- 改动必须可回滚、影响面可见：挂 1 个点还是 256 个点，是可用与不可用的区别。
- 用户说"停下来回顾"时，先算总账：哪些尝试已被证伪、哪些从未验证——别把"没试成"当成"试过了"。

## 8. 最终修复（2026-11-16，已实机确认）

- **实现**：在文本钩子 DLL 中新增可选师徽映射表读取；单独工作线程只校验并改写唯一已确认的调用点 `0x3ef56e`，目标不符或映射不可用时只禁用师徽修复，不影响文本钩子初始化。贴图请求热路径不写日志、不做进程全扫描。
- **映射**：新增 `mod/build_crest_map.py`，从 14 个原版剧本的 `Units.csv` / `OBs.csv`、四种语言映射和原版 `Dat/Art/Sym` 生成约 249 KiB 的表。当前 3,277 个可用映射；两个多对一译名被跳过，避免错误显示其他单位的徽记。
- **离线验证**：DLL 为 x86；合成 `.text` 测试通过；10,000 次原有文本钩子往返测试通过；简体师徽路径转换、非师徽路径不变、未知徽标名不变均通过；`finalize.py` 134 项 checksums 与全部构建守卫通过；映射新鲜度检查通过。
- **实机确认（2026-11-16）**：用户在第 1 装甲师详情页确认师徽显示，中文界面正常接入，启动与详情页无卡顿。版本定为 **v1.9.12**。
