# 「目录含有文件链接」误报（v1.10.3）

**日期**：2026-11-19 · **版本**：v1.10.2 报错 → v1.10.3 修复 · **范围**：只动启动器，数据层与 DLL 未动

## 一、玩家报了什么

玩家（漢化 1.9.15）的 Steam 库被「电脑管家」迁移过。启动器自动找到游戏后立刻报：

    目录含有文件链接，请将汉化包放到普通文件夹：c:\program files (x86)\steam

他把 `game_path` 手写成真实路径 `D:\电脑管家迁移文件\steam\steamapps\common\Gary Grigsby's War in the East 2` 之后就正常了。

玩家日志（`mod\logs\launcher.log`）：

两个要点：

1. 第 4 行把 **C: 的联接路径记进了 `settings.local.json`**，所以玩家不手改就每次重犯；
2. 手写真实路径后（11:24 起）一切正常——**汉化包、游戏文件、存档都没问题**，问题只在启动器的路径检查。

## 二、根因

- v1.10.2 的 `NoLinks(string path)` 从游戏目录起逐级向上到盘根，**任何一级**带 `FileAttributes.ReparsePoint` 就抛 `IOException`。
- 「电脑管家」的搬家做法：把 `C:\Program Files (x86)\Steam` 变成一个**指向 D 盘的目录联接**（junction），游戏文件本身仍是普通文件。
- Steam 注册表里的 `SteamPath` 仍是 C: 路径（搬家工具通常不改），启动器据此拼出 `c:\program files (x86)\steam\steamapps\common\...`，祖先命中联接 → 拒启动。
- 报错文案「请将汉化包放到普通文件夹」把责任推给汉化包位置，实际与汉化包无关，玩家无法据此自救。

## 三、复现（本机，不启动游戏）

```
mklink /J D:\Tool\_tmp\linktest\SteamJunction D:\Tool\_tmp\linktest\real\steam
# real\steam\steamapps\common\Gary Grigsby's War in the East 2\WarInTheEast2.exe 放一个假主程序
mod\WitE2CN.exe --prepare --game "D:\Tool\_tmp\linktest\SteamJunction\steamapps\common\Gary Grigsby's War in the East 2"
```

v1.10.2 启动器输出（与玩家日志同一条栈）：

```
FAILED System.IO.IOException: 目录含有文件链接，请将汉化包放到普通文件夹：D:\Tool\_tmp\linktest\SteamJunction
   在 Launcher.NoLinks(String path)
   在 Launcher.Prepare(String source)
   在 Launcher.Run(String[] args)
```

## 四、修复（`mod\src\Launcher.cs`）

| 位置 | 改动 |
|:--|:--|
| `Launcher.cs:105-128` | 删除 `NoLinks`，新增 `RealPath(string path)`：`CreateFileW(full,0,7,IntPtr.Zero,3,0x02000000,IntPtr.Zero)` 打开目录句柄 → `GetFinalPathNameByHandleW` 由系统解析全部联接 → 去 `\\?\` / `\\?\UNC\` 前缀 → `Length>3` 才 `TrimEnd('\\')`；任一步失败返回原路径 |
| `Launcher.cs:135-136` | `Files()` 只拦**游戏目录内部**的链接，提示改为「游戏目录内部含有文件链接，无法安全复制：<路径>」，并说明删除办法 |
| `Launcher.cs:498-503` | `Prepare()` 开头 `RealPath(source)`，路径变了就记 `游戏目录经链接解析：<原> → <真实>` 并把 `source` 换成真实路径；删除 `NoLinks(Root)` / `NoLinks(source)` / `NoLinks(Runtime)` |
| `Launcher.cs:755` 附近 | `--where` 额外输出 `GAME 真实路径 <解析后>` |
| `RealPath` 内 | 卷无盘符时 Windows 只给 `\\?\Volume{...}`，这种结果放弃解析、保留原路径 |

设计取舍：**祖先联接放行，树内链接仍拦**。前者对读取/复制透明，没有安全风险；后者会重复复制或递归，仍然必须挡。

## 五、验证结果

| 场景 | 结果 |
|:--|:--|
| 联接路径 + `--prepare` | 日志 `游戏目录经链接解析：D:\Tool\_tmp\linktest\SteamJunction\... → D:\Tool\_tmp\linktest\real\steam\...`，随后正常走到正版清单判定（假目录停在「检测到未经官方渠道安装的游戏」），**不再报链接** |
| 真实路径 + `--prepare` | 无「经链接解析」行，正版判定与退出码与 v1.10.2 完全一致 |
| 联接路径 + `--where` | 输出 `GAME <联接路径>` 与 `GAME 真实路径 <真实路径>` 两行 |
| 数据层 | 词典 74,489 条、四语言包、字体、场景 CSV、`WitE2CN_Text.dll` 全部未变；checksums 125 条通过 |

## 六、旧版应急话术（给玩家）

v1.10.2 及更早版本遇到此报错：把真实路径写进 `mod\settings.json` 的 `game_path`，或带参数 `WitE2CN.exe --game "<真实路径>"` 启动。不需要重装，也不需要移动汉化包。真实路径可以在资源管理器里打开游戏文件夹、从地址栏复制。
