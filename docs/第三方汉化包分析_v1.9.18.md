# 第三方汉化包技术分析（2026-11-18）

对象：D:/Tool/otherWITEmod/WITE2汉化测试_2026-10-16_09-09（真第三方测试包，70 文件 / 60,103,402 B）。
参照：游戏原版 D:/Tool/steam/steamapps/common/Gary Grigsby's War in the East 2；本仓库 v1.9.18；玩家反馈包 D:/Tool/WITE2/userfeedback/1。

同级的 D:/Tool/otherWITEmod/WITE2_CN-main 是我们自己 2026-10-24 的 GitHub 快照（text_hook.c 10,437 B、translations 70,866、无 VERSION），与本分析无关。

## 一、它改了三层：EXE、数据、字体

### 1) EXE：摘掉原壳，新增 .cave 段

| 项 | 原版 | 第三方 |
| --- | --- | --- |
| 文件大小 | 7,682,328 B | 10,360,832 B |
| 入口点 | 0x61C1310（在 .bind，Enigma 类保护壳） | 0x47A974（在 .text） |
| .cave | 无 | VA 0x6196000 / vsz 0x2E25A5 / raw 0x6FF200 / rsz 0x2E2600 |
| .text | vsz 0x50A983 | vsz 0x4D2943（小 0x38040） |
| .rdata | VA 0x50C000 | VA 0x4D4000 |

- .cave 开头是 x86 代码（首字节 53 57 8B 5C 24 10 = push ebx / push edi / mov ebx,[esp+0x10]），不是数据段。
- 代码之外是一张扁平的「英文\0 + GBK 中文\0」对照表：解析出 **19,199 对、6,525 个不同源串**。样例：Brigade→旅、Battalion→营、Army→集团军、Fort→要塞、Fortified→筑垒、STAVKA→最高统帅部、Transcaucasus Front→外高加索方面军、Luftflotte Reich→国土航空队。
- 6,525 个源串里 3,211 个我们词典已有、3,314 个没有；缺的里面有 1→装甲集群、2→集团军、117→英军轻型高射团 这类**裸 ID/番号键**。这说明它的查表不是纯显示层替换，键空间与数据 ID 混用过。
- 译文不是 UTF-16 存在 EXE 里：.text/.rdata 的汉字比例与随机数据同量级（约 30%），所以不是「把 EXE 字符串换成中文」，而是注入代码在运行期做替换。

### 2) 数据层：整表替换（与我们最本质的差别）

- Dat/GenData 只放 15 个 .dat（原版 20 个）：**w_unit.dat 与 w_city.dat 与官方 SHA-256 完全一致**（按说明书回退成英文）；其余 13 个大小全变：
  w_ac 60,934 / 62,317、w_air 41,042 / 42,019、w_device 18,843 / 19,152、w_factory 59,815 / 58,243、w_gameEvent 38,746 / 46,133、w_ground 48,307 / 49,752、w_gtype 3,355 / 3,399、w_leader 34,956 / 34,352、w_mapregion 5,405 / 5,470、w_maptext 97,780 / 98,626、w_nat 1,901 / 1,942、**w_ob 78,851 / 78,904**、w_pname 22,092 / 20,462（前=第三方，后=原版）。
- Dat/Scen 46 个文件全部与原版不同（23 .scn + 23 .txt）：.scn 普遍小 5–6 万字节（例 1941 Campaign.scn 1,880,512 vs 1,934,089）；.txt 简报是明文 UTF-8 中文。
- 所有 .dat 头都是 10 95 FF F9 E0 33 B4 F1 9E 79 ED …（与存档同族的加密容器），静态读不出内容，只能靠大小与说明书判断。

### 3) 字体：四套字重/斜体 + 按角色映射 + 地图字号缩小

- Dat/Fonts 四个字体：WITE2CJK.ttf 2,024,132 B、WITE2CJK-Bold.ttf 2,001,784 B、WITE2CJK-Italic.ttf 2,083,852 B、WITE2CJK-BoldItalic.ttf 2,062,492 B。
- FontConfig.txt 整份替换：1–40 号字体全部改成 WITE2 CJK（例 1,WITE2 CJK,14,0；6,WITE2 CJK,8,1；13,WITE2 CJK,13,0）。
- GuiFonts.json 按角色分派：常规给 FONT_MEDIUM/SMALL/LARGE/NARROW/EDITOR/CONSOLE/HEADER_SMALL/AOG 等，粗体给 FONT_UNIT/UNIT_SMALL/MAIN_TAB/SMALL_BOLD/HEADER/EVENTS_LARGE/MAP_32，斜体给 FONT_MAP_27/28/33/34/35/36/37 与 FONT_EVENTS_ITALIC，粗斜给 FONT_MAP_38/39/40 与 EVENTS_BOLD_ITALIC。
- 地图字号大幅下调：MAP_26 60→16、MAP_25 53→16、MAP_24 49→16、MAP_23 41→16、MAP_22 37→16、MAP_21 33→16、MAP_20 31→16、MAP_19 29→16、MAP_18 25→16、MAP_17 21→16、MAP_16 19→18、MAP_15 17→16、MAP_14 15→14、MAP_12 11→9、MAP_27/28 11→8 …（说明书自述「地图大字号已按 200% 显示缩放缩小」）。

### 4) 部署方式

- 启动汉化.bat 写 steam_appid.txt=1775550、设 SteamAppId/SteamGameId，然后启动同目录的 WarInTheEast2_CN.exe。
- 它**直接写在游戏目录里**（覆盖 Dat/GenData、Dat/Scen、Dat/Fonts、FontConfig.txt、GuiFonts.json）。代价：Steam 校验或更新会冲掉；不能与别的汉化共存；旧存档里的名字不跟着变；编辑器不能输入中文；存档文件名仍是 Save turn。

## 二、恶性 bug（预备兵库支援单位无法移动到战场）的机理

1. 他们自己在使用说明里写：「这一版把会触发程序按名字判断的几类名称改回英文：单位名和编制名 w_unit.dat、w_ob.dat；城市名 w_city.dat……工厂名 w_factory.dat；剧本里的兵牌签名和航空军名称。」——这等于承认：**数据层的名字会被引擎当查找键用**，翻掉就会失配。
2. 但回退不彻底：w_unit.dat、w_city.dat 确实与官方字节一致，**w_ob.dat 仍与原版不同**（78,851 vs 78,904），w_ground / w_device / w_leader / w_ac / w_air 也都不同。
3. 「把预备兵库里的支援单位移到战场」这个动作要解析该单位的上级司令部/编制归属（OB/HQ），w_ob 正是那张还带着译名的表 → 按名查找失败 → 走进异常路径（无反应或崩溃）。
4. 旁证：.cave 表里有 1→装甲集群、117→英军轻型高射团 这类裸数字键，说明注入层与数据 ID 有耦合；任何 ID 恰好等于某个键，就会被替换成中文，后续比较自然失败。

结论：这不是某一个 bug，而是「把显示名当数据键」这条路的系统性代价。他们在用「逐表回退英文」打补丁，但只回退了四张表，剩下的表仍会复发同类问题。

**我们不跟这条路**：本 mod 只翻显示层（WitE2CN_Text.dll 钩住本地化查表，词典 72,566 条），Dat/GenData、.scn、.dat 一律不动，引擎按名查找永远命中英文原值。

## 三、验证它到底栽在哪张表（不用启动游戏，也不用改游戏目录）

在第三方包的**副本**上做逐表回退二分（它自带 Dat，不依赖游戏目录）：

2. 仍崩则依次单独换 w_ground.dat、w_device.dat、w_leader.dat、w_ac.dat、w_air.dat，每步只换一个。
3. 判定：换哪张表后动作恢复正常，问题就出在那张表。

要点：

- 「他连事件内容也汉化了」的感受，来自他把数据层 100% 换成了中文；我们的事件正文其实已覆盖 97.9%，差的不是事件。

- 不要拿 1941 Campaign - No Early End 的 CSV 做基准：那份 GameEvents.csv / MapText.csv 在 2026-10-24 15:16 被改成过中文（见第六节），统计会虚高成「缺 273 条」。

## 五、可以学、且不破坏底线的四件事

1. **番号补译**（零风险，收益最大）：AirGroups 1,257 条 + AOGs 148 条，走现有词典层，一次构建即可。建议作为下一批。
2. **四套字重/斜体 + 按角色映射**：我们目前单字体，粗体/斜体全部用常规字形；可用 fontTools 从现有字库生成 Bold/Italic/BoldItalic，再按他们的角色表映射。纯观感提升，需改 integration/build_variants.py 与 GuiFonts 生成逻辑。
3. **地图大字号下调**：CJK 在 60px 下确实过大；建议只降 MAP_17–26（如 60→28、53→26、49→24…），保留小字号不动，避免地图文字过密。
4. **事件正文**：已覆盖 97.9%，剩余 7 条可顺手补；若以后要更全，用 1.9.18 的 trace 抓运行期未译串再补，不碰数据层。
