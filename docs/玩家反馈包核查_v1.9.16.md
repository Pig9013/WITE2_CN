## 四、百科表正文塌行（已修）

`Dat\Info` 的正文列由引擎直读、不走本地化查表，正确状态是游戏原版字节。`build_maps.py` 按 `(文件名, id 列)` 索引正文，而这几张表的 id 列**全为 0**：

| 文件 | 原版 | 修复前 overlay |
|:--|:--|:--|
| `deviceInfo.csv` | 3,552 B / 4 行 / 4 种正文 | 3,132 B / 4 行 / **1 种**（全是 Mosin M38） |
| `groundInfo.csv` | 2,461 B / 2 行 / 2 种 | 2,488 B / 2 行 / 1 种（KV-1） |
| `leaderInfo.csv` | 2,653 B / 2 行 / 2 种 | 3,309 B / 2 行 / 1 种（沙波什尼科夫） |

处置（沿用 v1.9.11 的 `unitInfo.csv` 先例）：

- `mod\build_maps.py` 的 verbatim 集合扩到四张表，命中时**把原版字节复制进 overlay**（不再跳过，保证 runtime 里的坏副本被盖掉）；取字时先 `utf-8-sig` 再 `cp1252`（`groundInfo.csv` 是 UTF-8）。
- `mod\restore_unit_info.py` 改为多文件：restore 逐字节写回、`--check` 逐字节比原版并清理语言包同名副本；`finalize.py` 的百科守卫输出 `Info guard: OK（…四张表均与游戏原版逐字节一致）`。
- `integration\build_variants.py` 的 `VERBATIM_NAMES` 加入这四张表（否则繁简转换会拿 UTF-8 硬解 cp1252 的 `0x96` 而崩）。
- `mod\publish.py` 增加变体目录镜像删除：仓库里删掉的旧副本要在安装目录一并删掉，否则 `payload\variants\zh-TW\overlay\Dat\Info\deviceInfo.csv` 这类坏文件会一直留着（overlay 只写不删）。
- `aircraftInfo / airGroupInfo / pilotInfo` 只有 1 行，不存在塌行，本轮不动。
